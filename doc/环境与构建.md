# 实验环境与构建（recipe 模型）

本仓库不把 QEMU / 内核 / busybox 源码放进 git，而是保存一份 **recipe**：

```
env/        进 git：版本 + sha256 + config + patch + rootfs overlay  ← "配方"
external/   不进 git：按 recipe 还原出来的源码树，可删可重建        ← "原料"
build/      不进 git：编译产物（QEMU/内核/initramfs/rootfs）        ← "产物"
```

这是 Buildroot/Yocto/OpenWrt 管理 BSP 的同一套思路：仓库里存 `版本 + 补丁 + 配置`，
源码按需拉取。总仓保持在 10MB 以内，换电脑只需要 recipe + 一条命令。

## 1. 一图看懂

```
linux-kmods/
├── lab.conf                     # 唯一版本来源：内核/busybox 版本与 sha256、QEMU base
├── env/
│   ├── qemu/
│   │   ├── configure.args       # 一行一个 configure 参数
│   │   ├── patches/<series>/    # 6 个 patch（vfpga/eeprom/tmp105/spi/gpio/edu）
│   │   └── series/<series>      # patch 顺序
│   ├── kernel/
│   │   ├── arm64-virt.config    # 完整 .config
│   │   └── README.md            # 以后加内核补丁的位置与流程
│   ├── busybox/
│   │   ├── busybox.config
│   │   └── rootfs-overlay/etc/{inittab,fstab,init.d/rcS}
│   └── virt/                    # 可选的 DTB / flash.img 生成脚本
├── external/                    # gitignore：qemu/ linux-*/ busybox-*/ .cache/
├── build/                       # gitignore：qemu/ kernel/ busybox/ rootfs/ initramfs.cpio.gz
├── scripts/
│   ├── bootstrap.sh             # 下载/解包/浅拉 QEMU/patch（make env）
│   ├── build_env.sh             # 编译（make env-*）
│   ├── pack_initramfs.sh        # busybox + overlay + 设备节点 + 运行库 → cpio.gz
│   ├── qemu_hack.sh             # QEMU 改动/导出/重放/换基线
│   ├── run_qemu.sh              # 起 QEMU（路径全部相对仓库）
│   ├── build.sh                 # 模块构建 / checkpatch / sparse
│   └── qmp_dev.py               # QMP/QOM 工具
├── drivers/ doc/ tests/         # 驱动/文档/测试（路径保持不变）
└── Makefile
```

## 2. 新电脑：三条命令

```sh
git clone <本仓库> linux-kmods && cd linux-kmods
make doctor        # 检查 git/gcc/aarch64-gcc/ninja/glib/pixman/cpio...
make env           # 还原 recipe + 全量编译（QEMU 10~20 分钟，内核 5~10 分钟）
make run           # 起虚机；另开终端 make verify 或按手动指南操作
```

只想要某一部分：

```sh
make env-fetch     # 只下载/解包 + 打 QEMU patch，不编译
make env-qemu      # 只编 QEMU（增量）
make env-kernel    # 只编内核 Image + modules（生成 Module.symvers）
make env-busybox   # 只编 busybox 到 build/rootfs
make env-initramfs # 只重打 initramfs
make modules       # 编 drivers/**（KDIR 默认 build/kernel）
```

可覆盖的路径/版本：

```sh
EXTERNAL=/data/lab-src BUILD=/data/lab-build make env
QEMU_SERIES=minimal make env-qemu-reset
KDIR=/some/kernel/build make modules
QEMU=/path/qemu-system-aarch64 KDIR=/path/kbuild INITRD=/path/initramfs.cpio.gz make run
```

> 本机已经有编译好的内核/QEMU/initramfs 时，可以完全绕过 recipe，直接用环境变量覆盖：
> `make KDIR=/path/to/kernel`、`QEMU=... KDIR=... INITRD=... tests/.../verify_qemu.sh`。
> 但 `make env-kernel` / `make env-busybox` 使用 `O=` 外部构建，**要求 `external/` 里的源码干净**
> （不能有 `.config`、`vmlinux` 等 in-tree 产物）；复用旧的 in-tree 构建树请只作为 `KDIR`。

## 3. 源码是怎么管的

| 组件 | 获取方式 | 版本 pin | 定制 |
|---|---|---|---|
| Linux | kernel.org `.tar.xz` | `KERNEL_VERSION` + `KERNEL_SHA256` | `env/kernel/arm64-virt.config` |
| busybox | busybox.net `.tar.bz2` | `BUSYBOX_VERSION` + `BUSYBOX_SHA256` | `busybox.config` + `rootfs-overlay/` |
| QEMU | `git fetch --depth 1 --filter=blob:none <base-sha>` | `QEMU_BASE` | `env/qemu/patches/<series>/` |

QEMU 不用 submodule，原因：

- 定制是 6 个 patch（约 200 行），`git diff` 直接可审；submodule 主仓只显示一个 commit 指针；
- submodule 要维护自己的 QEMU fork（推 447MB 历史），换机 `--recursive` 更慢；
- 内核 4.9 / busybox 都是 tarball 生态，做 submodule 需要 5GB 级内核仓库，没有收益。

需要看完整 QEMU 历史时，`external/qemu` 本身就是 git 仓库（`git log` / `git bisect` 可用），
只是它被视为可重建的工作区。

## 4. 改 QEMU 的标准流程

```sh
make env-qemu-hack                 # 切到 external/qemu 的 lab/work
vim external/qemu/hw/arm/virt.c
ninja -C build/qemu qemu-system-aarch64
make run
git -C external/qemu commit -am "lab: add foo sensor"
make env-qemu-export               # → env/qemu/patches/<series>/*.patch + series
git add env/qemu && git commit -m "qemu: add foo sensor"
```

- `make env-qemu-status`：看当前 base、series、lab/work 提交、脏文件。
- `make env-qemu-reset`：丢弃工作区，回到 `base + series`。
- `make env-qemu-rebase BASE=<新commit>`：换基线重放 patch；冲突时停在 `git am` 状态，
  解决后 `git am --continue`，再更新 `lab.conf` 的 `QEMU_BASE` 并 `make env-qemu-export`。

调 QEMU 自身用宿主 gdb：

```sh
gdb --args build/qemu/qemu-system-aarch64 -M virt -cpu cortex-a57 -m 2G \
    -kernel build/kernel/arch/arm64/boot/Image \
    -initrd build/initramfs.cpio.gz -nographic -append "console=ttyAMA0 rdinit=/linuxrc"
```

（`-s -S` 是 guest gdbstub，用来调客户机内核/驱动，不是调 QEMU 宿主代码。）

## 5. 改内核 / busybox

**内核**：只改了 `.config` 时，直接改 `env/kernel/arm64-virt.config`，然后
`rm build/kernel/.config && make env-kernel`（或 `make env-distclean` 全重建）。
要加内核代码补丁：在 `env/kernel/patches/` 放 patch，并在 `scripts/bootstrap.sh`
解包后、`make env-kernel` 前加 `git apply`/`patch -p1` 步骤（见 `env/kernel/README.md`）。

**busybox**：改 `env/busybox/busybox.config` 或 `rootfs-overlay/`，再
`make env-busybox env-initramfs`。

**initramfs**：`scripts/pack_initramfs.sh` 用内核自带的 `usr/gen_init_cpio` 生成 cpio，
因此不需要 root/fakeroot 就能写入 `/dev/console`、`/dev/null`。它还会：

- 从 `aarch64-linux-gnu-gcc -print-file-name=` 复制 `ld-linux-aarch64.so.1`、
  `libc/libm/libresolv`；
- 应用 `rootfs-overlay/`；
- 用 `gzip -n` 输出（不带时间戳，便于比对）。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| `external/qemu 有未提交改动` | `make env-qemu-export`（要保留）或 `git -C external/qemu stash`；`--reset` 会丢弃 |
| `lab/work 比 recipe 多 N 个提交` | 先导出 patch；否则 bootstrap 不会覆盖你的工作 |
| QEMU patch 应用失败 | 在 `external/qemu` 解决冲突 → `git am --continue` → `make env-qemu-export`；或 `make env-qemu-reset` 放弃 |
| 改了 `configure.args` 不生效 | 删 `build/qemu` 后 `make env-qemu` |
| 内核配置更新不生效 | 删 `build/kernel/.config` 或 `make env-distclean` |
| 客户机起不到 shell | `zcat build/initramfs.cpio.gz \| cpio -itv` 看 `linuxrc`/`etc/inittab`/`lib/`；确认 `make env-initramfs` 成功 |
| 驱动不 probe | 确认 `run_qemu.sh` 没传 `-dtb`（自生成 FDT 才带 tmp105 节点） |
| GCC 太新编不过 4.9 | 用 Ubuntu 24.04（GCC 13.3 已验证）或容器；见 `doc/开发规范.md` |

## 7. 清理

```sh
make clean          # 只清 drivers/** 的模块产物
make env-distclean  # 删除 build/ 与 external/（recipe 仍在，可重建）
```
